## Must-fix before launch (CRITICAL / HIGH) — ✅ DONE

| # | Sev | Where | What |
|---|-----|-------|------|
| C1 | CRITICAL | `customers/services/order_service.py:205` + `waiters:116` + `admins:199` | **Stale discount on item change.** `_recalculate_total` re-sums the *frozen* `OrderDiscount.discount_amount` instead of re-running `calculate_discount` against the new subtotal. Add items after a 20% discount → customer over-charged; remove items → drawer under-credited. Real money error on every order edited after a discount. |
| C2 | CRITICAL | `licensing/services/heartbeat.py:259-322` | **`register()` verifies no response signature.** `do_heartbeat()` verifies `X-Response-Signature`; `register()` does not. A MITM (or DEBUG plain-HTTP) can hand back an attacker-chosen key + forward-dated `server_now`, activating the install against a forged license. |
| C3 | CRITICAL | `licensing/services/heartbeat.py:40-55,171-201` | **Signed heartbeat has no nonce/freshness binding.** HMAC covers only the body; the sole replay guard is `server_now < last_server_now` (strict `<`, so an equal-timestamp replay re-arms grace). A captured signed ACTIVE 200 is replayable across clones and time → perpetual bypass. |
| C4 | CRITICAL | `base/services/sync/receiver.py:198-312` (FS1, still open) | **`_create_or_update` has no `transaction.atomic` + `select_for_update`.** Concurrent receives of the same UUID both pass `_should_replace` against the old version; the loser's `save()` clobbers the winner, defeating the deterministic tiebreaker. Non-atomic save+`_preserve_updated_at` can also leave `updated_at` un-stamped on crash. |
| H1 | HIGH | `customers/views/auth_views.py:~85-133` + `waiters/views/auth_views.py:~58-139` | **Customer/waiter auth endpoints skip session validation.** `me`/`logout`/`logout_all`/`change_password`/`sessions` don't use `@login_required`; the service path never checks `session.is_expired()`, `user.status==ACTIVE`, or UA-match. Expired/suspended tokens (and replayed stolen bearers) can still change passwords. Admin surface is correct; these two are not. |
| H2 | HIGH | `base/models.py:585-588,1071-1101` (FS3, pull path) | **`Table`/`Shift`/`CashReconciliation` emit FK UUIDs but have no `from_sync_dict` override.** On pull, the base impl drops `place_uuid`/`user_uuid`/`shift_uuid`; those FKs are non-nullable → IntegrityError or NULLed association on every cloud→branch pull. |
| H3 | HIGH | `base/models.py:58-63,105-114` (FS8, still open) | **`on_commit` queue failure = row never synced.** `_queue_for_sync` swallows exceptions; nothing re-scans `synced_at IS NULL`. A queue hiccup silently drops the row from sync forever. |
| H4 | HIGH | `stock/services/production_service.py:614-762` (SS2, still open) | **Nested `@transaction.atomic` + `set_rollback(True)` poisons the outer txn.** `complete()` owns an atomic, calls `_consume_ingredients`/`_create_output` which are *also* atomic and `set_rollback(True); return`. The outer then issues more ORM calls → `TransactionManagementError`, opaque 500, possibly inconsistent commit. |
| H5 | HIGH | `licensing/services/heartbeat.py:99-104` | **Fingerprint is Linux-only.** Reads `/etc/machine-id`; on Windows (the deploy target) falls back to hostname, so two same-named PCs share a fingerprint → clone detection defeated. |
| H6 | HIGH | `licensing/management/commands/activate_offline.py:74-81` | **Offline activation with no `--expires` = permanent un-revocable ACTIVE.** `last_heartbeat_at` stays None so `grace_until` is never computed; anyone with shell access gets a perpetual license. |
| H7 | HIGH | `admins/services/user_service.py:121-128` | **`update_user` silently drops `permissions`.** The view audits a `permissions` change as succeeded, but the service never writes it — permission grants/revokes are no-ops while the audit log claims success. |

## Should-fix (MEDIUM)

### Money / orders
- **M1** `customers/order_service.py:14` — POS flow never reaches `COMPLETED`; `loyalty.maybe_accrue` requires COMPLETED+paid, so **loyalty only ever fires from the admin service**. Orders are paid while still READY/PREPARING with no closeout. Add COMPLETED transition + call `maybe_accrue` in customer/waiter pay paths.
- **M2** `admins/services/order_service.py:691` (`mark_as_unpaid`) — unpay after cancel **reverses cash twice** (cancel reverses while `is_paid` stays True; later unpay sees `is_paid=True` and reverses again). Reject unpay when `status==CANCELED`. Also: unpay pulls cash with **no audit entry** (`admins/views/order_views.py:200`).
- **M3** `discounts/services/discount_service.py:197` (`update()`) — negative / >100% discount values validated only in `create()`, not `update()`. Add the same validation; reject PERCENTAGE `value>100`.
- **M4** `admins/services/inkassa_service.py:200-201` — collection `perform` saves balance with `update_fields=['current_balance','last_updated']` but **omits `synced_at`/`sync_version`**, so the new balance never propagates to cloud/peers (unlike `add_to_register`).
- **M5** `waiters/services/order_service.py:412` (`mark_ready`) — not `@transaction.atomic`, no row lock (every other ready path locks). Crash mid-flip leaves order READY with unready items; concurrent calls re-fire `on_order_ready`.

### Sync
- **M6** FS5 `base/models.py:73-79` — soft-delete doesn't cascade to children (Order→OrderItem, Place→Table); orphaned live children keep syncing.
- **M7** FS7 — soft-delete resurrection: a stale incoming `is_deleted=False` that wins the tiebreaker un-deletes a locally-tombstoned row. Make tombstones terminal.
- **M8** FS4 partial `base/models.py:253-261` — a payload with a naive `updated_at` raises `TypeError` in `_should_replace` and silently fails that record. `make_aware` both sides before compare.
- **M9** New: `from_sync_dict` overrides (Product:490, Order:768, OrderItem:862, Inkassa:972) return `'updated'` even when `_should_replace` is False → skips counted as updates, corrupting sync stats / masking conflicts. Return `'skipped'`.
- **M10** New: `base/services/sync/queue.py:97-122` — no dead-letter; a poison record retries forever and `push()` `break`s the whole model batch on first hard failure (`service.py:106`), blocking every later record for that model.

### Stock
- **M11** SS3 partial `stock/services/purchase_service.py:878-897` — `_update_po_status` reads `po.items.all()` + `po.save()` **without locking the PO row**; concurrent receivings on different lines race → PO stuck in PARTIAL. `select_for_update` the PO.
- **M12** NS1 `stock/services/order_service.py:157-166` — `REMOVE` modifier ("no onions") never credits the removed ingredient back → permanent stock leak per customization.
- **M13** NS2 `stock/services/production_service.py:579-589` — `_allocate_ingredients` discards `reserve()`'s status and marks ALLOCATED unconditionally; a failed reserve later makes release/consume hard-error (`level_service.py:387-390`).

### Server / deploy
- **M14** `Dockerfile:1` + `settings.py:160` — `python:3.14-slim` has no `tzdata`; `TIME_ZONE='Asia/Tashkent'` + `USE_TZ=True` raises `ZoneInfoNotFoundError` on first localtime conversion (attendance "today", shift boundaries). Add `tzdata` (pip or apt) — **will throw at runtime**.
- **M15** `entrypoint.sh:32,36` — heartbeat daemon backgrounded, then `exec gunicorn` becomes PID 1; daemon is orphaned, never signaled on `docker stop`, zombies unreaped. Add `init: true` to the `web` service.
- **M16** `alpha_pos/urls.py:53` + `base/middlewares/force_json_middleware.py:7` — `customers.urls` mounted at root `''`; JSON-wrapper middleware only exempts `/admin`,`/static`,`/media`. If `customers` ever serves browser HTML, error pages become JSON envelopes. Confirm API-only.
- **M17** `licensing/models.py:104-114` + `state.py:156-167` — two separate caches for License row vs state snapshot; a `QuerySet.update()` busts neither → up to 60s where a SUSPENDED row still reads ACTIVE. Drive both off one source / add signal.

tied to Soliq (tax authority). Currently `Order.payment_method` is recorded but
nothing fiscalizes. This is the deferred OFD item in ROADMAP/`WHATS_NEW.md`.
